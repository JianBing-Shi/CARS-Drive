日期：2026-11-04（Asia/Shanghai）。使用 epoch=19-step=3540 checkpoint；权重与训练代码未修改。原有 `evaluation/action` 保留。

## 范围与复现

- `existing_action_analysis.json`：原有完整验证结果的 1147 个唯一锚点，包含事件、recording、历史速度、转向与专家未来速度变化的描述性分组。
- `metrics.json` / `per_sample.csv`：新增配对诊断，按事件每组最多随机取 2 个，再全局去重，seed=1024，共 25 个锚点、5 个 recording。多标签锚点仅保留首次抽中的标签，因此不能将其事件均值当作完整事件宏平均。
- 本机 CUDA 不可用，新增实验在 CPU 完成。所有分支使用相同样本、模型、标签和坐标；正常分支逐批与生产 `forward()` 数值对照通过。
- 本次为机制诊断，没有原始 log bootstrap 区间，不是正式验收；新鲜输入均值不同于完整验证集是抽样分布不同所致。

```bash
conda run -n FRESH-Drive python tools/analyze_action_results.py --motion-groups
conda run -n FRESH-Drive python tools/evaluate_action_diagnostics.py \
  --config config/val/action_diagnostics.yaml
```

将 `samples_per_event` 改为 `null` 可评估全部唯一锚点。`scratch_dir` 仅复制引用的缓存到本地临时目录，避免重复读取慢盘；源缓存变更后应换新目录。没有向 `val.py` 加入线程数设置。

速度变化组由专家未来监督事后定义，仅用于分析，不是模型输入或抽样规则。模型在 5 个验证 recording 上的总体 ADE 均落后。基线重复最后一个历史 SE(2) 动作，包含准确的记录运动信息；模型仅通过视觉记忆和定位对齐间接获得运动信息，两者不是完全相同输入。

全量模型每步 dx MAE=0.0332 m、dy MAE=0.0030 m，累计 L2 从 0.1 秒的 0.0289 m 增至 1 秒的 0.3300 m。纵向运动估计与连续动作误差累积是重点检查对象，不能将全部误差归因于视觉无效。

## 新增配对诊断：1 秒回放

| 分支 | ADE，m | FDE，m |
| --- | ---: | ---: |
| 正常新鲜视觉，自回归 | 0.2057 | 0.4001 |
| 恒定动作基线 | 0.1199 | 0.2633 |
| 专家前一步动作前缀（仅诊断） | 0.0768 | 0.1283 |
| 仅保留历史，不再读新视觉 | 0.2599 | 0.7252 |
| 前 3 步缺观察，第 4 步起恢复 | 0.1913 | 0.3749 |
| 完全移除视觉（仅推理消融） | 7.8584 | 13.2359 |
| 用历史运动替换初始零动作（额外输入诊断） | 1.5236 | 2.2994 |

专家前缀显著降低误差，支持训练—推理动作前缀差异/自回归累积是重要因素；它使用未来专家信息，不能作为部署成绩或直接证明某一种训练修复有效。正常分支每步纵向偏差为 +0.0263 m，专家前缀分支降至 +0.0046 m。

移除视觉后输出失效，表明当前网络依赖视觉状态，但分布外破坏不能单独证明视觉有用。保留真实历史而不给新观察是较温和对照，误差也上升；仍需更大样本以及同条件训练的非视觉基线验证。

直接把历史动作塞进初始 previous 反而恶化，说明现有 checkpoint 训练时的零起始约定不能在推理时随意替换。若要加入历史速度/角速度，应作为明确输入重新训练，不能把该诊断当作现成修复。

缺帧后恢复分支在恢复阶段的局部位移误差为 0.0400 m/步，正常为 0.0415，持续不获取新视觉为 0.1051。本小样本中短暂丢帧没有恶化总体均值，不代表普遍获益或已经满足鲁棒性要求。

## 陈旧输入适配检查

| --- | ---: | ---: | ---: |

| 800 ms | 7.3325 | 12.6451 | 4.2786 |
| 1000 ms | 9.0840 | 15.4848 | 5.4020 |

延迟分支读取真实旧 BEV，保留来源位姿，并将旧 token 对齐到当前因果定位坐标系。时间表示 BEV 查询时间差，不是精确相机曝光年龄。窗口外历史不可用，不伪造补帧。

为检查混杂因素，去掉最早 10 帧但仍使用新鲜观测的 ADE=0.3395 m，明显低于 1000 ms 延迟的 9.0840 m，因此历史长度减少不能单独解释全部退化。将 1000 ms 延迟的 token 年龄错误标为零，ADE 降至 6.9213 m，但仍很差；年龄编码敏感性是可能因素之一。该错误元数据分支仅用于诊断，不能作为合法策略。

当前训练有单帧 anchor dropout，但这不等于学会持续延迟、混合区域年龄或固定上下文规划。以上只完成适配能力检查，**没有进行陈旧输入微调**。局部 token 对齐、时间分布与训练分布差异共同存在，不能据此唯一归因。混合区域年龄、真实重复帧与完整滚动恢复验收仍待补。

## 训练与选模证据、后续顺序

当前 `trajectory_loss_weight=0`，训练直接优化局部动作 SmoothL1，没有累计轨迹损失；这可能使小的有符号动作偏差累积，仍需受控训练实验验证。训练日志中 epoch17 的 val ADE=0.1582 m，epoch19=0.1697 m；当前报告用 epoch19，非日志最佳。二者为训练期的窗口加权验证统计，不能直接与去重后的主表混算。

建议按以下顺序继续，均需在训练集实施，使用验证集选模，不能根据这批诊断样本重新定义正式测试集：

1. 明确保存训练 split/hash、checkpoint 选择规则；按原有验证规则选取 epoch17 后在同一完整清单复核。
2. 对动作前缀失配做受控训练：在合法因果观察下增加自回归训练或动作前缀扰动；比较加入轨迹损失，控制其他设置一致。
3. 如加入历史运动，视觉/非视觉模型共享相同运动条件，分别训练，重新验证；不要修改现有权重的零起始约定。
4. 在训练集加入真实合法延迟、缺帧/恢复与固定五步视觉解码目标，冻结年龄/分组设置后用独立 log 验收；不能只训练随机单帧 dropout。
5. 先使五步候选达到预定误差与基线改善要求，再冻结预测器训练 refresh。动作预测与刷新策略改善分别报告。

新增诊断 3 项测试、既有指标 14 项数值测试通过。没有修改模型训练、没有启动重新训练，也没有将本次 25 锚点诊断当作正式泛化证据。
