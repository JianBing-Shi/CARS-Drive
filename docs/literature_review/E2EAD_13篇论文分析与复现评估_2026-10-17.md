# 13 篇自动驾驶论文：方法、开源、数据、模型规模与审稿评估

核查日期：2026-10-17。对象：用户提供的 13 份完整 PDF，包括正文、实验、附录和可读取的表格；代码状态另查作者仓库。目标：为已复现 Plan-R1、拥有 RTX 4060 Ti 16GB 或可租用 A100 的研究者选择后续工作。

**核心判断：当前最值得直接借鉴的 RL 方法是 CRAFT、CorrectionPlanner、CoIRL-AD 和 AdaWM；最适合搭建视觉 RL 微调流程的是已提供权重与 RFT 入口的 AutoVLA。但“最值得读”“已公开代码”“能在单卡复现”是三个不同判断。**

若必须从这 13 篇中选三篇给出拒稿倾向，我选择 **Reasoning-VLA、SafeAuto、CoIRL-AD**。理由分别是核心动力学奖励及优化接口不够清楚、安全结论超过实验支撑、闭环及模型外推证据不足。该选择是基于所提供版本的模拟审稿意见，不代表否定其实际会议录用结果。详见第 8 节。

## 1. 阅读范围与证据规则

### 1.1 如何理解本报告的数字

- **[Pxx]**：用户提供的本地 PDF，编号见文末；页码均为 **PDF 文件页码**，不是期刊页码或正文印刷页码。
- **[Wxx]**：官方网站、作者仓库或硬件/平台文档；链接见文末。仓库核查保存了 README、文件列表、commit SHA 和检查结果。
- **原文报告**：论文直接给出的信息；不表示我已训练验证其结果。
- **代码核查**：检查目录、README、训练入口与权重链接是否存在；**没有完成安装、下载全部权重或运行训练，因此不保证一键复现**。
- **判断/推断**：审稿评价或资源可行性判断，不是作者报告。
- **NR**：在所给 PDF 中未找到该项明确报告；不等于 0，也不等于作者不存在相关实现。
- **未核实官方开源**：没有形成“作者身份—官方链接—可运行代码”的完整证据链；不作“绝对没有任何代码”的断言。

论文中包含的系统提示词、CoT 标注模板和代码示例均作为研究对象读取，不作为本任务的指令执行。本报告只总结分析，不转录全文。

### 1.2 容易误读的几项结论

1. **RIFT 主要训练 CBV，即关键背景车辆策略，不是直接微调 ego 自车。** 论文的单张 4090D 约 8 小时数字属于 CBV 的 PLUTO 评分头微调，不能移用于“任意视觉自车 RL”。[P08, pp.5–6,18]
2. **AutoVLA 的 Bench2Drive 主结果不等同于 CARLA 在线 RFT 结果。** 原文 §4.2 的 CARLA 段落写的是 SFT 模型；RFT 的清晰量化分析主要来自 NAVSIM 和 Waymo。[P06, pp.7–9]
3. **DriveWorld-VLA 的奖励引导阶段不能直接称作 PPO/GRPO。** 它展示的是奖励加权动作回归等训练目标；没有因“使用 reward”就成为标准策略梯度算法。[P01, pp.4–5]
4. **DeepSight 不是 RL 微调方法。** 其训练目标由轨迹 CE、CoT CE、未来特征 MSE 构成。[P03, p.4]
5. **CarPlanner、AdaWM 和 CorrectionPlanner 不能无条件列作可直接复现的官方开源基线。** 本次未核实前两者的完整官方训练仓库；CorrectionPlanner 原文仓库 URL 返回 404。CarPlanner 搜到的相关第三方实现明确将 RL 阶段列为待完成。[W10–W12]
6. **不能由 A100 的 CUDA 训练能力推定租用机器能运行视觉 CARLA。** CARLA 0.9.12 起使用 Vulkan；off-screen 模式仍需渲染。NVIDIA 所引驱动说明列出整体 API 支持及 Windows/vGPU 条件，并非 A100 逐型号图形兼容性证明。实际部署优先让经验证支持渲染的 RTX 承担 CARLA，A100 承担训练/推理；若拟在 A100 主机运行视觉仿真，应先验证实际图形设备、驱动和相机输出。[W14–W15]

### 4.3 如果后续要真正补齐 Params/FLOPs

完整报告至少应同时提供：`P_total`、`P_trainable`、`P_deploy`、单次决策 FLOPs、一次 RL update 的实际计算、仿真交互预算。后者不能只用一次 forward 代表。

参数计数可用 `sum(p.numel() for p in model.parameters())` 与 `sum(p.numel() for p in model.parameters() if p.requires_grad)`；必须说明是否包含冻结 teacher、reference policy、world model 和视觉 encoder，共享模块不可重复计数。

FLOPs 测量必须固定 batch、相机数、分辨率、历史帧数、agent/map token 数、预测时域、候选数量、CoT token 数、diffusion/flow 步数、自纠正预算，并声明 1 MAC 算 1 次还是 2 次 FLOPs。动态生成应分别记录 prefill、decode 及端到端决策开销。缺少这些输入时，给一个“总 FLOPs”数字反而会误导。

本次没有安装 13 个模型环境，也没有下载全部 checkpoint 做 profiler；因此表中 NR 是有意保留的证据缺口。

### 5.2 三个最影响横向比较的细节

**AutoVLA 的 best-of-N 是 oracle 选择。** 原文 p.9 明确从 6 个候选中使用 oracle scorer；表 1 的 92.12 PDMS 应作为带额外选择信息的结果看待。更适合作为可部署单策略 RL 对照的是 post-RFT 的 89.11，且仍需沿用对应评测协议。[P06, pp.7,9]

**CRAFT 使用 Bench2Drive*。** 附录 B 修改 actor 清理、超时、BicycleFlow、特定路线流速、碰撞终止及不可见 stop sign 等。Table 4 做了协议 sanity check，这是优点；但主实验采用单 seed，同协议内相对改善与原版 Bench2Drive 榜单优劣要分开论证。[P07, pp.15–16]

**DeepSight 区分 Think2Drive 与 PDM-Lite 专家分布。** 主表把不同专家来源灰显，不能把不同 expert 的数值当完全受控比较。DeepSight DS/SR 更高的同时，comfort 从 AutoVLA 的 39.33 降至 16.11，表明多指标存在实际代价。[P03, p.5, Table 1]

## 6. 逐篇分析：创新点、证据、不足和可迁移价值

### 6.1 DriveWorld-VLA

**研究问题。** 让 VLA 不仅预测动作，还能在共享潜空间中预测动作引起的未来，再用未来评价动作。

**真正的创新。** 三阶段训练串联 VLA/世界模型联合学习、action-conditioned flow matching、未来引导的动作优化。BEV 不只是辅助输入，也承担共享表征和未来预测目标。[P01, pp.3–5]

**证据。** NAVSIM v1 PDMS 91.3、v2 EPDMS 86.8；nuScenes 平均碰撞率 0.16%。有阶段/监督/文本/扰动消融与腐蚀测试，覆盖面较完整。[P01, pp.6–9]

**不足与审稿疑问。**

- Stage 3 的奖励加权回归与严格策略梯度不同；若主张 RL 创新，应明确随机策略、优化目标及奖励如何反传。
- 离线数据主要提供实际发生的一条未来；action-conditioning 能否可靠外推未执行动作，需要独立反事实验证。生成未来“看上去合理”不能充分证明动作的因果效果。
- 主评测以 NAVSIM pseudo-simulation / nuScenes 开环为主，尚不能建立长时交互式部署结论；H20 上 1.16Hz 也限制实际应用。
- README 的训练 24h、表中 EP 81.9 与 PDF 的总约120h、EP85.9 不一致，需以具体配置和日志澄清；不能选较小预算替代原文。[W01; P01, pp.5–8]

**对你有用的部分。** 只借用“候选动作 → 未来状态 → 评分”的接口，把轻量结构化世界模型用于时间奖励研究；暂不完整复现多阶段 2B VLA。

### 6.2 SafeAuto

**研究问题。** 语言模型的数值输出精度、规则遵守与历史案例利用不足。

**真正的创新。** PDCE 将数字位置与距离纳入 CE；MLN 把交通谓词/规则用于高层动作后验校验；多模态 RAG 使用视频、控制和环境谓词检索历史案例。[P02, pp.3–6]

**证据。** BDD-X 上行为文本指标改善，DriveLM 上高层行为准确率 74.60、轨迹 ADE0.84；给出了谓词、检索数量和损失敏感性等消融。DriveLM 的 UniAD-Full ADE0.80，说明其优势不是所有低层轨迹指标都领先。[P02, pp.7–9]

**不足与审稿疑问。**

- 主要证据是 QA、数值误差、规则谓词违背率，没有提供对应的长期交互闭环事故/成功率；因此“safe driving”应作窄范围解释。
- MLN 的有效性依赖检测器与谓词提取；若关键信号错误，逻辑校验本身不保证动作安全。需要错误传播及不确定性分析。[P02, pp.5–6,9]
- PDCE、MLN、RAG 三部分是否构成统一方法，还是三个独立增量，需要更强交互消融；并应提供直接连续回归/动作 token 等替代方案。
- 多组件检索、检测、可能的重新提示带来部署开销，完整系统参数、端到端延迟和 FLOPs 未明确量化。

**对你有用的部分。** 交通规则可转成约束奖励或 safety critic 标签；但不要仅把 RAG 接到 Plan-R1 上就作为主要 RL 贡献。

### 6.3 DeepSight

**研究问题。** 像素/码本未来生成偏重纹理，且顺序预测未来开销较大；希望预测更有利于驾驶的语义未来。

**真正的创新。** 用 learnable world queries 并行预测 BEV 中未来 DINOv3 语义特征，再结合自适应 CoT 生成轨迹。把语义表征预测而非图像重建作为未来监督。[P03, pp.3–5]

**证据。** 官方 220 路线主表 DS86.23、SR71.36%；去掉 adaptive CoT 后 DS84.52、SR65.91%。有 latent/VAE、前视/BEV、单/多帧消融。[P03, pp.5–7]

**不足与审稿疑问。**

- 原文典型预测间隔0.5s，共覆盖当前到未来约2s；“long-horizon”是相对前人短时设置，不宜扩写成分钟级规划。[P03, pp.3–4]
- 不具备清晰的 action-conditioned 可交互动力学接口；未来特征预测器不能自动当成 RL simulator。
- 引入 DINO 教师、约1.3M CoT标注和64张H20，需要预算匹配的消融才能分离方法与资源收益。
- comfort16.11 明显低于表内 AutoVLA39.33，不能以总分掩盖平顺性代价；高算力下闭环可运行也不证明低延迟部署。[P03, pp.4–6,8]

**对你有用的部分。** 未来特征可作辅助 critic/risk representation；更适合作为固定编码器或小规模特征蒸馏，而不是完整训练复现。

### 6.4 Reasoning-VLA

**研究问题。** 自回归数值生成慢且可能丢失精度，统一多数据集时还需适应不同车辆和场景。

**真正的创新。** 几何统计初始化 action queries、与 VLM cross-attention、并行连续轨迹回归、SFT后接GRPO；轨迹误差与动力学启发式奖励联合。[P04, pp.3–5]

**证据。** nuScenes 7B平均L2为0.23；NeuroNCAP平均分2.25、碰撞率59.4%；H200上“10 Traj”口径报告0.089s，但该措辞需要澄清。公开仓库仍是占位。[P04, pp.6–8,15; W04]

**不足与审稿疑问。**

- **核心物理定义有问题。** p.5 Eq.(2)用 `abs(Δy/Δx)<0.84` 作为 steering 约束。这是线段方向的斜率，不能直接等于前轮转角：车辆沿斜向直线行驶可以曲率为0、所需转角为0；真实转向约束应结合曲率、轴距等。该式也有 `Δx≈0` 的数值问题。
- Eq.(3)约束相邻线段长度变化，只反映某种切向速度变化，不能覆盖横向加速度或完整车辆动力学。论文的“物理可行”结论需要更严格验证。
- 连续回归 action head 如何形成 GRPO 需要的可采样策略和 log-prob，正文未充分说明；若RL只更新语言token，又需说明 reward 怎样有效训练连续动作模块。
- 统一8数据集时，轨迹GT、坐标系、时间采样、车辆状态与切分来源应公开，特别是 Mapillary/IDD 这类数据的运动监督构造，当前无法从公开代码复核。
- Table3中RL并非处处改善：Waymo平均L2 0.21→0.22，Mapillary0.47→0.49，IDD0.36→0.37；进一步nuScenes微调后NeuroNCAP2.25→2.19。结论应承认负迁移。[P04, pp.7–8]

**对你有用的部分。** 并行规划头和物理奖励问题本身值得研究；不要直接照搬它的转向奖励。后续用曲率、横向加速度、jerk及kinematic tracking检查可行性。

### 6.5 CoIRL-AD

**研究问题。** IL拟合专家、RL优化奖励，两种目标可能冲突；纯专家离线数据又缺乏足够反事实覆盖。

**真正的创新。** 双actor分别优化IL/RL，通过周期性竞争合并/复制参数；latent world model估计未来价值，group sampling与critic结合；inverse causal mask和step-aware sampling辅助规划。[P05, pp.3–5]

**证据。** 常规nuScenes平均L2约0.63、碰撞0.18%；跨城市的改善较大；有IL/RL融合方式、mask、world model、BC权重等消融。附录Table11也比较CQL、PPO-lite。[P05, pp.7,14–17]

**不足与审稿疑问。**

- 评测主要是nuScenes开环，没有独立CARLA/nuPlan交互闭环证据；“RL改善闭环分布偏移”的核心因果链仍弱。
- 离线world model在偏离专家数据时可能失真；作者也因此设γ=0.5。尚缺动作外推误差、critic偏差与reward exploitation的定量分析。[P05, p.14]
- 用固定阈值合并actor是有效工程机制，但是否强于预算匹配的简单BC正则、蒸馏或PPO，需要细分。Table11中PPO-lite碰撞0.16优于0.18，L2·Col0.10也优于0.11，方法并非对该复合指标占优。[P05, p.17]
- 主文长尾集描述基于baseline表现，附录改成对双方hard cases求并集；附录已缓解单方选择偏差，但两处表述需统一。基于模型表现定义的长尾集仍应补充独立语义规则子集。[P05, pp.6,15–16]

**对你有用的部分。** 将“IL/RL目标冲突”作为一个可检验问题；可先尝试共享编码器+独立小head与受控蒸馏，避免未经消融直接叠双策略。

### 6.6 AutoVLA

**研究问题。** 语言动作输出的物理约束、推理成本以及固定长CoT的不必要开销。

**真正的创新。** 用可解码motion token统一语言和动作；SFT学习fast/slow双模式；用驾驶reward与CoT长度惩罚做LoRA RFT，学习减少不必要推理。[P06, pp.4–7]

**证据。** NAVSIM one-shot80.54→post-RFT89.11 PDMS；有group size、数据规模、tokenization、运行时间分析。CARLA主表DS78.84/SR57.73，但该段写明模型采用SFT，不能归因为CARLA在线RL。[P06, pp.7–10]

**不足与审稿疑问。**

- best-of-N92.12用了oracle scorer；必须与可部署选择器区分。
- fast平均1.072s、slow10.518s，与实时传感器闭环仍有距离；仿真可暂停等待，不代表真实车辆可等待。
- 长度惩罚可能压制真正必要的推理，应检查复杂度与风险分层下的触发准确率及事故尾部。
- 仿真主结果和RFT结果分属不同设置，不能把全部收益都归为RL；reasoning annotations尚未全部公开也影响从头复现。[W06]

**对你有用的部分。** 使用已发布SFT checkpoint，只做小规模RFT；冻结视觉端、缩短生成、减少group size并测峰值显存。是视觉方向可优先尝试的工程基础，但不保证原配置16GB适配。

### 6.7 CRAFT

**研究问题。** 闭环真实执行反馈稀疏，反事实候选反馈密集却有模型偏差，怎样组合二者？

**真正的创新。** 在当前策略访问到的状态上算counterfactual proxy advantage，用真实交互关键事件作grounded residual correction，并用EMA teacher和非对称KL稳定微调。重点是优化信号角色分工，不是新视觉骨干。[P07, pp.2–6]

**证据。** 三类策略均优于同设置GRPO/PPO等；SparseDriveV2评分版本DS66.43→71.10，MindDrive62.60→67.45；有组件、规模、迁移和稳定性分析。[P07, pp.7–9]

**不足与审稿疑问。**

- 修改Bench2Drive协议且主实验采用单seed；附录协议sanity check的多seed不能替代算法自身多seed统计。
- 只更新评分/决策模块，候选生成固定，不能创造候选空间里不存在的安全动作；这是复现优势也是能力上限。[P07, pp.17–18]
- 理论分解是理想advantage层面的恒等关系，实际用事件启发式近似residual；还需量化代理与真实advantage的相关性、偏差和失效场景，不能把理论分解视为实际估计无偏证明。
- LEAD→Bench2Drive迁移DS仅+0.58、RC−0.34，说明分布外收益较小且有进度代价。[P07, p.8]

**对你有用的部分。** 与时间信用分配最直接相关。可以研究“何时proxy可信、何时需要真实纠正，以及纠正应分配给哪个时间步”，但必须超出照搬proxy+residual。

### 6.8 RIFT

**研究问题。** 生成自然、可控、能与自车交互的背景交通；把nuPlan预训练策略迁到CARLA时存在covariate shift。

**真正的创新。** 对PLUTO全部候选做前向评估和group-relative优化，采用equal-weight、冻结generation head并训练scoring head、dual-clip稳定负advantage更新；服务于CBV风格控制。[P08, pp.4–6]

**证据。** 有三seed的运动分布、交互、地图指标；比较不同AV在生成交通中的表现，有normal/aggressive奖励及模块消融。[P08, pp.7–9]

**不足与审稿疑问。**

- 对齐速度/加速度分布不等于还原人类条件行为；CARLA中没有对应反事实人类GT，realism证据应作有限解释。
- equal-weight目标不再是原policy期望下的标准无偏PG；作者也承认ratio是更新调节器，应按新surrogate理解，不直接套用标准GRPO保证。[P08, p.6]
- 固定generator限制新动作探索；专家覆盖不足时难以继续改善生成质量，作者明确讨论。[P08, p.26]
- 正常/激进风格有安全—效率权衡，不是所有指标都最好；初始ego/CBV组合的偏好可能影响场景“可行性”判定。

**对你有用的部分。** 若只做自车RL，它是辅助工具；若选择“针对规划器的交互式困难场景生成”，它可以成为直接基线。不要把两类任务的指标混写。

### 6.9 CarPlanner

**研究问题。** 自回归逐步采样导致模态不一致、探索空间大，难以高效进行RL轨迹规划。

**真正的创新。** 固定跨时刻的模式表示、generation-selection架构、Invariant-View Module及专家引导reward，利用PPO训练轨迹generator。[P09, pp.3–6]

**证据。** nuPlan Test14-Random非反应式94.07，反应式91.1；分析RL/IL对ego-history dropout与backbone sharing的不同需求。[P09, pp.6–8]

**不足与审稿疑问。**

- 训练采用非反应式其他agent未来预测，测试reactive受到扰动时略弱于PDM-Closed91.64；作者承认训练/测试交互差异。[P09, pp.4,7]
- 专家距离reward可能限制超越专家的探索，作者在limitations明确讨论。[P09, p.8]
- 测试规模为261/318场景的两个split；不应扩写为完整nuPlan全部长尾或视觉E2E验证。
- 完整官方训练资产未核实，第三方仓库RL未完成，增加直接复现成本。[W10]

**对你有用的部分。** 固定模态与时间一致性、RL/IL梯度冲突以及reactive训练缺口；保留你现有Plan-R1工程比重写CarPlanner更划算。

### 6.10 AdaWM

**研究问题。** 预训练世界模型/策略在新任务上RL微调可能先退化，应该更新世界模型还是策略？

**真正的创新。** 分析性能下降与model/policy mismatch的关系，用失配判别自适应选择更新对象；世界模型用低秩适配，策略用子单元组合权重更新。[P10, pp.4–7]

**证据。** CARLA右转、左转、环岛、不同交通密度和城镇迁移；单V100预训12h+微调1h；77M模型配置。[P10, pp.8–10,19]

**不足与审稿疑问。**

- 理论中的最优策略偏差/真实转移分布与实现中的经验TV代理不完全相同，需验证失配检测是否真的识别了正确更新对象。
- 经验TV在高维连续状态中的估计方法、样本需求和阈值C敏感性影响可靠性；不能仅凭理论上界证明实际切换最优。
- 实验使用CARLA特权信息构造BEV，并非从相机直接学感知；少量特定任务迁移不能等于完整Bench2Drive220评测。[P10, pp.7–8,19]
- 未核实官方代码，且没有从更广泛的不同世界模型/不同初始策略证明普适性。

**对你有用的部分。** 可以把“reward变化”和“世界模型失真”分开诊断，避免在模型错误时盲目强化策略。预算相对友好，工程要自己补齐。

### 6.11 Raw2Drive

**研究问题。** 特权BEV上的MBRL有效，但从原始视频学习世界模型和reward较难。

**真正的创新。** 特权/原始双流世界模型；rollout中对齐编码、确定/随机状态并协调采样；利用特权reward/continuation head指导raw policy训练。[P11, pp.4–7]

**证据。** CARLA v2/Bench2Drive闭环；消融覆盖head guidance、RSSM共享、直接用特权policy与raw微调的区别。[P11, pp.8–10]

**不足与审稿疑问。**

- 仿真提供的GT框和HD-map是重要训练特权；真实数据里标签噪声/缺失会怎样传递，仍缺验证。
- raw/privileged状态对齐不意味着真实环境的模型误差被消除，尤其是传感器盲区与交互外推。[P11, pp.10,25–26]
- 64 H800 GPU-days约1536 GPU-hours；复用Think2Drive仍约960 GPU-hours，不属于单卡轻量微调预算。
- 作者仓库目前没有实际源码，阻碍独立核验。[W09]

**对你有用的部分。** 若以后把结构化Plan-R1迁向视觉，可以做轻量teacher/student迁移；当前不建议从零重训双世界模型。

### 6.12 Robust Autonomy Emerges from Self-Play

**研究问题。** 不使用人类驾驶轨迹训练，是否能靠大规模多agent自博弈获得鲁棒且自然的驾驶策略？

**真正的创新。** 面向多agent大规模训练的GIGAFLOW系统、行为条件化/随机化、自博弈和advantage filtering；核心是可扩展交互训练及其涌现行为证据，而不是大参数网络。[P12, pp.1–8,17–19]

**证据。** 约16亿公里、1万亿transitions；同一策略零样本用于CARLA LAV、nuPlan、Waymax；长时仿真鲁棒性和WOSAC realism；actor/critic各3M。[P12, pp.1–8,19,23]

**不足与审稿疑问。**

- 抽象感知栈，主要是结构化planning/control；不能将其结论写成原始传感器端到端的成功。
- “几百万公里一次事故”是在特定合成分布与参数设定下的仿真统计，不能直接等同真实道路事故率，作者也明确承认sim-to-real边界。[P12, p.8]
- 需要严格拆分自博弈、多agent、reward随机化和环境规模各自的贡献；规模曲线与消融有帮助，但不是所有现实失败都被覆盖。
- 未核实可获取完整GIGAFLOW代码，且1900 GPU-hours之外还有高吞吐仿真工程门槛。

**对你有用的部分。** 用少量行为条件化背景策略测试泛化；不要照搬超大规模目标，也不要因只有3M参数就低估训练成本。

### 6.13 CorrectionPlanner

**研究问题。** AR规划器提出危险动作后，如何在执行前利用失败历史主动修正？

**真正的创新。** propose-evaluate-correct的motion-token闭环；collision critic触发纠正，保留unsafe proposals形成correction trace；IL后用REINFORCE+KL强化最终执行token。[P13, pp.3–6]

**证据。** Waymax reactive碰撞1.68 vs SMART2.36；nuPlan Val14 NR91.22；有trace、无纠正RL、rejection sampling、candidate selection、critic阈值及预算消融。[P13, pp.7–9]

**不足与审稿疑问。**

- collision critic的precision/recall强烈影响保守性；0.8阈值recall仅0.31，0.7阈值precision仅0.21；需要校准和分布外风险分析。
- 最大纠正次数耗尽时，算法最终执行最后proposal，**没有安全保证或必然安全fallback**。[P13, p.15, Algorithm4]
- RL只把trajectory reward分给最终执行token，中间失败token缺少直接信用；这是你的时间/纠正链信用分配可能切入的位置。[P13, p.5]
- Test-hard NR75.37低于SMART76.39，默认0.434s延迟也应与更强现代planner和预算匹配候选搜索比较；不是所有设置最好。[P13, pp.7,9]
- 8×H800训练且代码URL不可访问，当前直接复现成本偏高。

**对你有用的部分。** 在已有Plan-R1上实现小critic和有限次数纠正，比重新训练VLA更契合你的起点；研究难点应是纠正链信用与模型偏差，而非只增加一个拒绝采样循环。

## 7. 4060 Ti 16GB / A100 的实际选择

以下是**工程判断，不是已完成的显存实测**；单张A100还必须区分40GB/80GB。租卡前应确认主机CPU、RAM、SSD、驱动、图形API及数据存储条件。

| 路线 | 4060 Ti 16GB | 单张A100 40/80GB | 判断依据与建议 |
|---|---|---|---|
| 已有Plan-R1上改reward/advantage/小critic | **最优先**：沿用已跑通配置 | 适合扩大实验 | 你已有实际工程基础；先做增量显存和吞吐测量 |

| CRAFT + 小型评分策略 | 适合单worker、串行collect/train的原型，不承诺原论文速度 | 可承担trainer | 原文8×4090D、6–10h；基础模型和视觉采集仍要计算 |
| AutoVLA3B LoRA RFT | **有条件尝试**：从SFT权重起步，减少图片token、生成长度和组数；可能仍OOM | 80GB更适合；40GB需测 | 当前官方配置2卡、rank8，不是16GB测试报告；改QLoRA属于新配置 |

| DriveWorld-VLA / DeepSight完整训练 | 不建议 | 单A100仅适合缩规模/冻结模块探索 | 原文8×H20或64×H20；多帧视觉、教师与世界模型开销大 |

**A100+CARLA的可行分工。** 用有图形支持的RTX运行CARLA和相机采集，将buffer/特征送往A100训练；若跨公网传输图像，带宽与延迟可能抵消收益。只开`-RenderOffScreen`并不会取消传感器渲染；`no-rendering`又不适用于需要相机图像的实验。已有纯结构化nuPlan任务不受同样图形渲染要求限制。[W14–W15]

不建议给出“4060训练8小时、A100训练2小时”这种未测承诺。最低可用性试验应记录：100–1000次update是否成功、peak allocated/reserved memory、rollout frames/s、updates/s、生成长度与candidate count、CPU/RAM占用。只有这些量测后才能外推实验预算。

## 8. 如果我是审稿人，会拒哪三篇？

### 8.1 评价边界

这是**在同样重视方法明确性、证据与主张匹配、独立验证的前提下的相对选择**。不以“没有代码”或“我只有16GB显卡”为拒稿理由，也不把Nature的广泛读者要求冒充ICML官方标准。所有评价基于所提供PDF版本；未看到的材料记为未证实，不凭空指控造假、泄漏或实验错误。

### 8.2 审稿报告一：Reasoning-VLA——倾向 Reject，置信度中高

**优点与读者价值。** 并行动作query能减少序列生成开销，多源训练与闭环测试具有实用价值，适合VLA和规划研究者。

**主要拒稿理由。**

1. **动力学核心奖励与所声称物理量不对应。** Eq.(2)的斜率不能代表steering，因而“通过奖励保证物理可行”的论据不成立；这是方法层面的问题，而非缺少某一个benchmark。
2. **连续回归与GRPO优化接口不明确。** 缺少可核验的采样分布、trajectory likelihood及其对action head梯度路径说明；仅说使用GRPO不足以重建算法。
3. **RL泛化证据并不一致。** Table3多数据集退化，7B+的NeuroNCAP也下降；需要明确收益边界和统计稳定性。
4. **统一数据与效率口径需要核查。** 运动标签构造、坐标/时间统一、训练测试切分，以及0.089s是否包含推理与全部视觉处理，没有足够公开资产可重核。

**会改变判断的补充。** 修正为曲率/轴距/横向加速度约束，给出连续策略的完整GRPO定义，发布统一数据生成规则；在预算匹配、含完整端到端延迟的多seed闭环实验中证明收益。[P04, pp.5,7–8,15]

### 8.3 审稿报告二：SafeAuto——倾向 Weak Reject，置信度中

**优点与读者价值。** 数值token损失、规则校验和检索构成可插拔工具，代码/权重可见；对安全知识融合与驾驶问答有价值。

**主要拒稿理由。**

1. **安全主张与证据不匹配。** QA和规则一致性改善没有建立“实际执行后更安全”的结论；缺少闭环事故、near-miss、红灯/让行及路线完成率联合验证。
2. **验证器安全性受观测错误制约。** 需要测试漏检红灯、错认车道适用规则、谓词矛盾与检索错误；目前的校验层不能据此称作安全保证。
3. **统一技术贡献不够有力。** 三模块都合理，但对预算匹配的较简单连续预测/动作token+规则约束基线，是否存在不可替代优势尚需更强证据。

**为什么不是强拒。** 若定位为“知识增强驾驶理解和控制信号预测”，原文结果有价值。拒稿倾向主要针对其更广的安全驾驶主张，不是要求所有VLM论文都必须做CARLA。

**会改变判断的补充。** 缩小安全结论或补交互闭环测试；给谓词错误注入、验证器校准、规则冲突与端到端开销，并与简单强基线公平比较。[P02, pp.5–9]

### 8.4 审稿报告三：CoIRL-AD——倾向 Weak Reject / Borderline Reject，置信度中

**优点与读者价值。** IL/RL冲突是真问题，双actor竞争有清晰动机；开源资产较完整，跨城市结果和融合策略消融值得肯定。

**主要拒稿理由。**

1. **尚未证明对实际闭环分布偏移有效。** 学习世界模型中想象rollout与真实交互闭环不同，nuScenes开环改善不足以证明长期安全收益。
2. **world model偏差是方法核心风险，却缺少校准验证。** 尤其离线专家数据上探索OOD动作时，模型可能给出虚假高价值；γ=0.5能抑制长程误差，但不是解决证据。
3. **复杂框架的必要性还未充分建立。** 附录PPO-lite在碰撞与L2·Col上更好，双策略的额外训练成本约为LAW两倍；应以相同计算、相同初始化、相同模型rollout对照独立评估。
4. **长尾评价需要外生定义。** 对双方困难样本求并集优于只挑baseline失败集，但仍可能对特定模型敏感；最好给独立场景语义规则定义的长尾集。

**为什么它仍值得读。** 它的IL/RL目标冲突、world-model error与部署单actor设计有明确研究价值；“可借鉴”与“当前证据足够录用”不是同一结论。

**会改变判断的补充。** 加一个独立交互闭环平台；报告世界模型OOD误差与模型利用行为；加入预算匹配的PPO-lite/BC/蒸馏强基线，给多seed置信区间。[P05, pp.5–7,14–17]

### 8.5 三份意见的综合判断

最明确的方法疑点在Reasoning-VLA；SafeAuto和CoIRL-AD更接近“结果有价值，但结论或验证范围不足”。另外三篇也需重点追问：CRAFT的patched protocol/主实验单seed，DriveWorld-VLA的反事实因果主张与低频推理，DeepSight的资源控制与comfort代价。这些并不自动使其进入我选择的前三篇。

我没有选择Raw2Drive或Self-Play，仅因其未核实代码或算力大就拒稿：前者展示了特权→raw传感器MBRL桥接，后者展示大规模自博弈的跨基准现象，科学贡献与复现门槛应分别评价。

## 9. 针对你已有 Plan-R1 的研究建议

### 9.1 优先保留一个中心问题

建议聚焦：**在世界模型存在误差时，如何把真实闭环风险事件的责任分配给正确的轨迹时间步/纠正步骤，并以有限交互预算改善策略？**

与现有工作关系要逐项说清：

- 对Plan-R1：不是仅把reward改成`[batch,time]`，而是改变advantage/梯度中的时间归因，并检验其实际作用。
- 对CRAFT：不只是proxy+residual相加，而是研究残差该作用在哪个时间步以及模型不可信时如何调整。
- 对CorrectionPlanner：不只训练最终接受token，研究失败proposal和纠正链怎样获得有效学习信号。
- 对AdaWM：区分策略失误与世界模型失真，避免对模型错误作错误信用分配。

这些是候选问题，不是已证实的新颖性声明。真正投稿前需对最新相关工作做专项查重，并用初步结果决定主线。

### 9.2 最小可执行实验序列

1. **在现有nuPlan工程上建立严格对照。** 原版、仅dense reward、仅return-to-go、逐步advantage归一化、完整新方法。把reward、return、advantage和token log-prob分别存日志。
2. **先做一个受控信用分配诊断。** 同一场景中人为制造早期危险动作、晚发生碰撞；看算法是否把梯度分配给真正相关动作。防止只因碰撞惩罚更强获得提升。
3. **检查模型偏差。** 固定策略，比较world model预测风险和独立simulator执行风险；按误差大小分层报告方法增益，避免模型自评形成自证循环。
4. **加有限预算自纠正或critic。** 对照同等policy调用次数的rejection sampling、best-of-K和候选评分；避免把更多推理预算误写成算法贡献。
5. **先完成nuPlan标准闭环，再考虑Bench2Drive迁移。** 迁移需要视觉/状态接口与独立策略，不是把nuPlan权重直接放进CARLA。若资源有限，先在小型视觉评分策略上复核算法即可。

### 9.3 哪些指标与成本必须一起交付

安全、进度、舒适、成功率、长尾分层、至少3seed及置信区间；同时给环境步数、wall-clock、GPU-hours、参数总量/训练量、候选数、world-model rollout次数、完整决策p50/p95延迟和显存峰值。
m
训练和测试路线/城镇要分开，原版Bench2Drive和任何patched protocol要分开。**不要默认三套基准、大VLM和大世界模型同时上；一个可验证算法问题加充分对照，比模块数量更能形成清楚的论文。**
