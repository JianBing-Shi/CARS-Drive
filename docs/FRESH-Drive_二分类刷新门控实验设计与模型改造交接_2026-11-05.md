# FRESH-Drive 二分类刷新门控：实验设计与模型改造交接

日期：2026-11-05（Asia/Shanghai）。用途：交给模型修改会话作为需求与实验协议。本文件总结已确认目标和建议实现；二分类门控尚未接入运行代码，不能据此宣称已完成或已验证。

2026-11-06 用户确认扩展：新增[轨迹修订模块 v3](../../docs/trajectory_revision_v3.md)。核心是“哪些环境变化说明旧规划已经落后，以及当前候选是否作出了正确响应”。动作预测器结构与权重保持冻结；新增适配器由专家 L1 经冻结 decoder 的输入梯度训练，二分类继续学习是否采用，合法历史候选提供辅助偏好监督。当前 v3 每帧生成候选，不再沿用下文 v2 的在线 keep 路径省解码主张；v2 保留为历史基线。

实现更新：二分类门控已作为本轮第一版接入，具体实现选择、版本、测试与训练入口见[二分类刷新 v2 结构定稿](../../docs/binary_refresh_v2.md)。首版采用完整当前缓存 BEV 监测及固定全有效 BEV 更新；尚未正式训练，不能将下文实验目标当作已验证结果。

## 1. 已确认的研究目标

FRESH-Drive 研究针对突发事件的轨迹刷新：**学习何时需要放弃旧轨迹、采用新轨迹，何时应继续沿用旧轨迹。** 不以刷新区域数量或候选预测精度单独代替这一目标。

已确认的分工如下：

| 模块 | 职责 |
| --- | --- |
| 动作预测器 | 每次输出一个连续局部动作 `[dx, dy, dyaw]`；保持单步预测器 |
| 五步解码 | 连续调用同一单步预测器五次，通过 SE(2) 积分得到 0.5 秒候选轨迹 |
| 刷新分类器 | 输出“不刷新／刷新”两个 logits，经 softmax 得到概率 |
| 规划执行模块 | 不刷新则保留旧计划剩余部分；刷新则生成并采用新计划 |
| 区域选择（如保留） | 决定刷新哪里，属于独立于二分类时机门控的功能 |

不改为独立五步并行输出头，不默认新增专家运动状态输入。旧文档中的五步并行、运动学残差等历史提案不属于本轮确认要求。

## 2. 为什么需要改变现有刷新目标

当前 `FreshModule.fresh_targets()` 的监督为：

\[
U_r=E(\text{旧视觉重新规划})-E(\text{刷新区域 }r\text{ 后重新规划})
\]

该量回答“新视觉是否帮助重新规划”，无法直接回答“是否应放弃当前正在沿用的轨迹”。当前代码在预测区域收益大于零时直接替换旧计划，目标与执行动作存在差距。

本轮主要监督应改为：

\[
W_t=E_{M_t}(P_t^{keep},G_t)-E_{M_t}(P_t^{new},G_t)
\]

- `P_keep`：旧计划删除已经过的端点，并变换到当前自车坐标系后的有效剩余轨迹。
- `P_new`：按部署时相同的观测更新方式、动作上下文和冻结预测器生成的新五步轨迹。
- `G`：当前时刻之后的专家轨迹，仅用于训练监督和离线评分。
- `M`：旧计划、新计划和专家标签在相同绝对未来时间上的共同有效前缀。
- `E`：共同端点上的二维欧氏距离均值，单位米。不能把旧计划零填充部分计入误差。

例如保留旧计划误差 0.5 m、旧视觉重新规划 1.0 m、新视觉重新规划 0.8 m，则 `U=+0.2 m`，但 `W=-0.3 m`：视觉更新有帮助，替换旧计划仍有害。保留 `U` 作为诊断，主要门控应对应 `W`。

## 3. 输入边界：观察环境不等于替换轨迹

如果不刷新时完全不接收任何当前信息，旧记忆无法识别此前不可见的新突发事件。必须明确当前监测信号的来源与成本，不能只增加分类头就宣称能检测新事件。

建议首先把“是否替换轨迹”做成清楚可验证的主实验：使用截至当前已到达的因果观测构造监测表示，门控判断是否需要更新规划。即使当前 BEV 不写入规划记忆，只要分类器读取了它，也属于视觉获取，必须记录。

| 设置 | 可验证的研究主张 | 成本边界 |
| --- | --- | --- |
| 每步可用当前缓存 BEV，门控决定是否重规划 | 学习轨迹刷新时机与规划计算节省 | 不宣称省去每步图像／BEV 编码 |
| 低成本当前监测，触发后才获取完整或区域证据 | 学习证据获取和轨迹刷新 | 需要明确实现监测器，计入监测、探测和完整更新开销 |

两种设置是实现建议，不是均已确认或均已实现。第一版建议固定一种，所有策略共用相同信息与更新方案。不得在实现中隐含选择另一种设置，再将收益归因于门控。

分类器建议读取：当前监测表示、旧视觉记忆、证据年龄、旧计划及有效掩码、剩余步数、合法动作上下文；如研究成本权衡，再加入预算与成本。当前 `queries` 来自旧视觉重规划，不能直接代替旧计划输入。

## 4. 二分类头与执行逻辑

使用普通 MLP／融合编码器加两维线性输出即可，网络容量作为后续受控因素：

```python
logits = refresh_classifier(context)     # [B, 2]
probabilities = logits.softmax(dim=-1)
request_refresh = probabilities[:, 1] > probability_threshold
```

类别固定为 `0=继续旧计划`，`1=刷新并替换计划`。`probability_threshold=0.5` 是未校准起点；需要调整时仅在开发验证集确定，正式比较前固定。

```text
每个 0.1 秒决策点：
    更新当前定位与时间，裁剪并对齐旧计划
    更新独立保存的合法动作上下文
    若旧计划仍有效：
        分类器输出刷新概率
        若请求刷新且所需证据／预算可用：
            获取或更新约定的新证据
            调用同一单步预测器五次，采用新计划
        否则：
            继续旧计划剩余部分
    若旧计划耗尽：
        按统一期限维护规则生成新计划
        标记 deadline_replan，不伪装成事件刷新
```

在“不刷新且未到期”的在线路径中，不应先生成完整新轨迹才决定是否生成它。离线制作标签／评分需要的额外候选，应与部署推理分开，不能混入节省计算的计时结果。

分类器请求、预算是否允许、是否实际获取证据、是否采用新计划分别记录，防止分类正确但执行不可行被掩盖。

## 5. 标签、损失与区域选择

在有共同有效端点、旧计划尚未耗尽、部署更新动作可行的决策上构造：

\[
y_t=\mathbb{1}\{W_t>\epsilon+\lambda C_t\}
\]

`epsilon` 是预先定义的最小有意义改善量；`C` 若包含成本，应将 `lambda*C` 换算到与 `W` 一致的收益单位。二者可先不启用成本项做消融，但必须记录设置。标签阈值和推理概率阈值是不同参数。

训练采用：

```python
loss = F.cross_entropy(logits[decision_valid], labels[decision_valid])
```

交叉熵接收原始 logits，不先 softmax。没有合法门控标签的 batch 应产生可反传的零损失，不能导致 NaN。

标签与训练必须满足：

1. 不把“带事件标签”直接等同于刷新正类；事件存在并不意味着替换旧计划有收益，背景场景也可能需要刷新。
2. 计划耗尽时没有合法 keep 对照，应从时机分类损失及分类指标中排除；不能强行赋正类。
3. 候选与旧计划都使用当前以前的合法输入，专家未来仅用于算 `W`。修改未来 GT 应改变标签，但不改变分类输出和实际决策。
4. 新候选采用与部署一致的证据更新方案。若仍有区域选择，标签应评价实际选择器产生的候选；不能用真值最佳区域的收益标正，再在部署时换成较差区域。
5. 最简实验可先固定区域／更新方案，只学习二分类时机；之后再研究联合学习“何时”和“哪里”。区域范围是否为全部 BEV 不由本文件自动决定，需在配置和报告中明确。
6. 检查训练集正负类比例；需要时使用训练集统计的类别权重。不要用验证／测试统计构造训练权重，也不要为追求低刷新率人为大量标负。
7. 在部署式滚动状态上生成标签，或明确记录离线状态采样策略并补充 on-policy 滚动复核；不能仅在每步全部更新的状态上训练，再声称适用于长期保留计划。

`W` 只评价当前共同剩余时间，不等于长期驾驶回报；旧计划只剩一两步时要单独报告支持量与效果，不对缺失尾部伪造五步旧轨迹。

## 6. 必须先修正的滚动接口

当前 `RollingPlanner` 使用 `previous = plan[:, 0]`。旧计划根据日志定位多次平移后，首端点可能包含跟踪残差，不能继续当作同一种单步动作上下文。

模型修改时需要分离保存：

- `previous_action`：上一段预测中的局部 SE(2) 动作，具有明确参考帧和时间间隔。
- `retained_plan`：当前坐标系下的剩余累计端点与有效掩码。
- `remaining_steps`：剩余计划长度。

建议从采用的动作序列独立保存和推进动作上下文，首次仍遵循已约定的零初始化；不得直接把重对齐端点作为动作，也不默认引入专家动作或新增实际运动输入。若要改用因果里程计，应另立输入扩展实验，训练与所有基线保持一致。

每次候选五步独立初始化 decoder hidden；各候选状态独立，不将反事实候选写回真实记忆，不读取未来 BEV／定位。该约定与持续观察训练的差异仍需验收，不能仅依靠接口测试证明预测可靠。

## 7. 两阶段训练

### 阶段 A：动作预测器

当前代码已实现连续单步 v2，固定 L1；配置为：

```yaml
teacher_forcing_ratio: 0.0
action_loss: l1
xy_loss_weight: 0.50
yaw_weight: 0.10
trajectory_loss_weight: 0.35
heading_loss_weight: 0.05
```

四项系数之和为 1。累计位置项是**坐标 L1**，不是欧氏 ADE；系数大小不代表实际梯度贡献大小。记录四项原始损失和加权损失，保持单步质量为重点，同时验收五次递推。

现有累计监督来自逐步接收已到达视觉的十步回放；固定视觉五步目前用于验收，并未自动成为训练目标。是否加入候选任务适配，应作为独立受控训练实验。

验收包括下一步 dx/dy/dyaw MAE 与偏差、持续观察 ADE/FDE、固定视觉五步 ADE/FDE，以及静止、稳速、加速、减速、转向分组。运动学基线如使用准确历史运动，必须注明与 BEV-only 模型的信息差异。

### 阶段 B：刷新二分类器

加载合格 action checkpoint，冻结并 eval tokenizer／视觉记忆／动作 decoder。训练新增门控及明确约定的监测融合层，不同时改动预测器来归因刷新收益。

二分类头需要新训练。旧收益回归 checkpoint 不包含这个分类头，不能直接当作新门控权重；网络与监督版本均需写入 checkpoint。恢复训练时检查版本，不以 `strict=False` 隐藏不匹配。

第一版以分类交叉熵训练，不默认额外加入多种辅助损失。选模规则、概率阈值及刷新预算在开发验证阶段确定；以实际轨迹质量和刷新成本共同验收，不能只看 accuracy 或分类 loss。

## 8. 数据与时间协议

沿用现有 nuPlan 缓存、原 train/val 按录制来源的划分；保持记录清单／hash，测试集不用于选模型或阈值。

| 阶段 | 相对事件标签时间 | 原窗口 slot |
| --- | --- | --- |
| 初始化历史与首次五步计划 | -2.0～-0.5 秒 | 0..15 |
| 十个决策点 | -0.4～+0.5 秒 | 16..25 |
| 每次新候选 | 当前之后五步，0.5 秒 | 当前 slot 后 1..5 |
| 最晚监督终点 | +1.0 秒 | 30 |

refresh 继续保留原事件锚点（`anchor_offset_us=0`）及 background_control。全局均值按 `(recording, anchor_timestamp_us)` 去重；事件报告保留原多标签关系，不能因去重只保留一个标签后称作完整事件宏平均。

原事件标签时间不一定是突发事件真实发生时刻。没有核验起点时只报告相对标签时间曲线，不声称精确事件检测延迟。每个 recording 内的重叠窗口不视为独立样本。

## 9. 对照实验与评估指标

所有策略使用同一冻结预测器、信息条件、时间协议、动作上下文和期限维护规则。

| 对照 | 要回答的问题 |
| --- | --- |
| 无事件刷新，仅到期重规划 | 不提前替换计划时的基准表现 |
| 每步更新并重规划 | 持续重规划的质量与成本参照，不保证误差最低 |
| 每步旧视觉重规划 | 区分视觉更新与重新解码的作用 |
| 固定频率刷新 | 学习时机是否优于预设时间表 |
| 同平均刷新成本的随机触发 | 学习时机是否优于随机策略；多随机种子 |
| softmax 二分类刷新 | 本轮主方法 |
| 同状态真值 oracle 刷新（仅诊断） | 当前预测器是否存在可利用的刷新收益，不作为可部署成绩 |

固定频率、随机和学习门控在同预算／相近实际刷新率上比较；无刷新和每步刷新作为成本端点单独报告，不冒称同成本对照。若研究区域选择，另做区域策略消融，不与时机门控的收益混算。

主要报告：

- **实际采用轨迹质量**：共同有效端点 ADE/FDE（注明实际时域）、下一步端点误差，必要时分剩余长度报告。
- **刷新时机分类**：刷新类 precision／recall／F1、混淆矩阵、PR-AUC、正负样本数量。不可仅报 accuracy。
- **必要性与漏判**：有效 `W` 标签上的不必要刷新率、漏刷新率；背景刷新率单独报告，不能直接等同误报率。
- **事件响应**：有可靠事件起点时报告触发延迟与未响应比例；排除期限维护触发，不能用首次到期重规划伪装事件响应。
- **成本**：事件触发率、期限重规划率、总重规划率、新证据获取量、监测开销、实际在线路径延迟；缓存区域数量不能代替完整编码 FLOPs。
- **预测器诊断**：固定五步候选 ADE/FDE、旧视觉与新视觉候选收益 `U`、相对 keep 的收益 `W`。未执行候选的误差不称作实际执行成绩。

输出全局、事件、运动状态、剩余长度和 recording 分组，报告有效支持量、P90/P95及逐样本配对差值。在有可靠原始 log 身份与足够独立 log 时做成组置信区间；少量 DB 名称不能直接当大量独立场景。

离线逐分支 oracle 只衡量该采样状态下的诊断潜力，不是整个动态策略的严格最优上界。日志回放中车辆不按模型轨迹移动，不宣称闭环避险或驾驶成功率；闭环 benchmark 在基础协议稳定后另行接入。

## 10. 已有结果如何使用

旧 refresh epoch 37、内嵌 action epoch 19 的 v1 权重，425 个窗口去重得到 392 个锚点，来自 5 个 recording：

| 旧策略 | 固定五步 ADE / FDE，m |
| --- | --- |
| no_refresh | 1.2549 / 1.8049 |
| learned 区域收益策略 | 1.2708 / 1.8138 |
| replan_only | 1.3718 / 1.9762 |
| cyclic | 1.4917 / 2.1522 |
| all_fresh | 1.8330 / 2.6659 |

这些是候选指标；旧接口的 `previous` 语义和重规划频率也是混杂。旧 learned 刷新率约 99.95%，成本系数为零，未证明学会时间稀疏刷新。

结果用于说明改造动机，不能据此断言视觉刷新无效或二分类一定改善。当前 v2 与新四项 L1 权重尚无本表对应的正式性能结果。应保留旧结果作为历史记录，修正接口后以新协议重新训练和复评，不覆写成新版成绩。

必要验证：强制分类为 0 时未到期不替换；分类为 1 且可行时替换；到期始终有有效计划且不污染分类标签；未来 GT／未来视觉扰动不改变当前决策；候选制作不写回真实状态；正负标签方向正确；`previous_action` 不被日志跟踪残差污染；旧 checkpoint 不被误载为新门控。

运行统一使用 Conda `FRESH-Drive`，Python 命令为 `conda run -n FRESH-Drive python ...`。本文件仅完成设计交接，不修改网络、不启动训练、不承诺新方案已优于基线。
