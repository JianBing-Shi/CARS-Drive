# 轨迹修订模块 v3（Trajectory Revision Module，TRM）

日期：2026-11-06（Asia/Shanghai）。本版对应第二轮刷新结构修改。动作预测器沿用已训练的连续单步 v2；本版只训练新增刷新侧模块。完成代码与接口验证不代表已验证真实轨迹质量，正式刷新训练与服务器性能验收仍需单独完成。

## 研究目标与职责

核心问题是：**哪些环境变化说明旧规划已经落后，以及当前候选是否作出了正确响应。**

新增模块命名为“轨迹修订模块”，因为它既修正规划表示，也判断是否采用修正后的候选。原 `RefreshGate` 的二分类功能保留为其中的采用判断；不将这个模块称为已验证的事件检测器，不将潜变量梯度直接解释为物理制动或避让方向。

| 组成 | 职责 | 是否训练 |
| --- | --- | --- |
| 原 BEV tokenizer、视觉记忆、单步动作 decoder | 提供已有视觉表示与连续动作生成能力 | 冻结且保持 eval |
| 因果时序与旧轨迹融合 | 读取轨迹相关的场景演化 | 训练 |
| 潜变量适配器 | 修正送入冻结 decoder 的规划表示 | 训练 |
| 新旧轨迹比较头 | 判断新候选是否值得替换实际旧计划 | 训练 |

不增加五步直接输出头，不新增扩散模型或离散动作，不使用专家动作前缀作为正式输入。候选仍调用同一个单步头五次并经 SE(2) 积分。

## 信息流与梯度

每个决策点读取当前及过去已到达的 BEV。监测历史与规划记忆分开：未采用新轨迹时，监测器仍接收当前信息；候选状态不因离线评分而写入实际状态。

历史观测使用当前以前的定位对齐，空间 token 保留位置和有效掩码。旧轨迹端点及相对未来时间构成 query，读取时序 BEV 和旧规划记忆，兼顾轨迹附近变化与从其他区域接近的目标。

潜变量适配器从冻结记忆更新产生的基础表示出发，输出有界残差。新候选路径为：

```text
当前以前 BEV、旧计划、合法动作上下文
    → 时序／轨迹条件融合
    → 可训练潜变量适配器
    → 冻结的单步 decoder 连续调用五次
    → 新五步候选
    → 专家 L1
```

冻结参数与关闭计算图是不同操作。tokenizer、基础记忆更新可以在无梯度路径计算；适配后的表示进入 decoder 后必须保留对输入的梯度，才能把专家监督反传给适配器。decoder 参数本身不更新。

候选轨迹进入二分类比较与后续滚动状态时应按明确边界 detach，避免分类目标借助改变候选来改变自己的标签，或者意外跨十个时刻反传。每次五步候选独立初始化 decoder hidden，候选内部不读取未来 BEV、未来定位或专家动作。

## 三项训练目标

默认目标为：

\[
L = 1.0L_{trajectory} + 1.0L_{adopt} + 0.25L_{history}.
\]

这些系数是明确记录的初始设置，不代表最优，也不代表三项梯度贡献相同。

### 专家轨迹 L1

每个合法决策点都生成新五步候选，不受当前采用标签控制，避免模型只在已被门控选中的时刻得到轨迹监督。对连续有效前缀使用位置坐标 L1，并加 0.1 倍周期航向 L1：

\[
L_{trajectory}=\operatorname{mean}|\hat p-p^*|
 +0.1\operatorname{mean}|\operatorname{wrap}(\hat\psi-\psi^*)|.
\]

这里只提供 L1 轨迹监督，不恢复 MSE、SmoothL1 等损失入口。ADE/FDE 仍是独立的欧氏评价指标。动作阶段原有四项 L1 配方与 checkpoint 不变。

### 实际旧计划与新候选的采用判断

主对照必须是当前正在沿用的旧计划，而非任意历史候选。对共同绝对未来时刻计算：

\[
W_t=ADE_{M_t}(P_t^{keep},G_t)-ADE_{M_t}(P_t^{new},G_t).
\]

沿用 `W > epsilon + cost_weight * update_cost` 标签，用原始二分类 logits 的交叉熵训练采用头。即使存在事件，新候选更差时仍监督保留；不强制“最新候选更好”。到期时不存在合法 keep 对照，从此项监督与分类指标排除，但仍可使用合法新候选的轨迹 L1。

未来专家轨迹只生成损失／偏好标签。改变未来真值可以改变监督，不能改变当前候选、比较概率或采用决策。

### 仍有效历史候选的辅助比较

历史候选先裁剪已过去端点，再对齐当前坐标。五步时域下，前一、二、三、四帧的候选分别最多保留四、三、二、一个未来端点；更早候选不再有共同未来，不能充作当前可执行计划。

每对历史／当前候选使用自己的共同有效时间前缀，由专家误差生成二分类偏好，并训练同一比较头。历史候选不直接被拉近或推远；它们可能优于新候选，也可能更差。各配对时域不同，不将其误差混成一个无条件全局排名；历史损失独立归一化，权重不随窗口内配对数量增大。

## 滚动与部署成本

沿用当前窗口：slot 15 建立初始五步计划，slot 16..25 作十次决策，每次监督到未来第五步，最晚 slot 30。当前只有一条专家轨迹即可评分模型自己产生的新旧候选，不要求多条专家响应。

本版是**先生成候选、再判断采用**：每个可行决策点生成一次五步候选，包括最终拒绝的候选。没有省去这些解码调用。初始规划、每帧候选、期限处不可行更新所需的回退解码、离线诊断解码分别记账；理论调用计数不是 GPU 实测时延。

旧计划到期时独立执行期限维护，不伪装为事件正例。预算不足或当前视觉无效时遵循统一回退规则，不能继续使用已经耗尽的旧计划。

当前每步仍读取完整缓存 BEV，不能声称减少图像或 BEV 编码。实际写入规划证据与是否采用轨迹需要分别解释；候选计算产生过的证据和算力不能因为候选被拒绝而不计入成本。

## checkpoint 与训练

保留 v1／v2 类和加载路径，新协议使用 `refresh_version: 3`。不能直接覆盖旧门控类，否则 action checkpoint 中当时保存的旧门控参数可能无法严格恢复。

从 action checkpoint 新建 v3 时，只严格复制 tokenizer、memory、decoder；新模块重新初始化，不恢复 action 优化器。动作网络版本、hidden_dim、空间网格、层数与 decoder 配置必须匹配。v3 断点续训核对刷新协议和新增损失／适配器设置，不使用 `strict=False` 隐藏不匹配。

默认训练配置已指向现有：

```text
lightning_logs/action_v2_gate2/version_1/checkpoints/best.ckpt
```

仅需执行刷新阶段：

```bash
conda run -n FRESH-Drive python train.py --config config/train/refresh.yaml
```

本版按实际采用轨迹的 `val/ade` 保存 top-3 和 last，同时记录轨迹 L1、主分类与历史分类损失。阈值只在开发验证集确定；val YAML 的 checkpoint 需填写训练完成的新权重。

## 验收与归因

必要工程验收包括：专家 L1 能给适配器产生非零梯度；动作组件参数与缓冲区训练前后完全一致；全无效监督不会产生 NaN；历史长度与坐标／时间对齐正确；未来 BEV／GT 不影响当前推理；旧 action 严格加载和 v3 恢复均成功。

真实数据评价必须同时观察候选质量、实际采用轨迹质量、有害替换、漏掉有收益替换、历史配对支持量、期限重规划及全部解码开销。分别报告不同剩余计划长度和事件组，不只看分类 accuracy。

固定、随机、每步采用与学习采用策略应共享同一个冻结动作预测器和同一个已训练适配器，才能比较采用时机。再用未适配的基础动作预测器作独立对照，区分适配器提高候选质量与采用判断带来的收益，不能全部归于二分类门控。

配对评估已包含 `all_fresh_base` 和 `no_refresh_base`：分别关闭适配器并采用每步／仅到期策略。比较 `all_fresh` 与 `all_fresh_base` 检查修订作用；比较共享适配器的学习、固定、随机和每步采用策略检查替换判断。`_base` 控制仍沿用相同的每帧候选计费路径，不冒充针对基线优化过的部署时延。

场景标签不等于核验过的事件起点；没有可靠起点时不报告精确提前预警或检测延迟。现有固定初始相位会让五步计划在标签时刻到期，需在正式实验中做不同合法计划相位的复核，并将期限触发单列。日志专家回放不等于执行候选后的闭环结果，专家贴合度也不等于安全保证。

已有 action 评估显示固定五步仍弱于使用准确历史运动的恒定动作对照；新模块是否改善这一问题必须通过真实训练后统一重评估确认。本版不承诺仅靠门控或潜变量适配即可补足预测器的全部能力。
