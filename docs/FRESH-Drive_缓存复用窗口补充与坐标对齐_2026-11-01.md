# 缓存复用、窗口补充与坐标对齐

保留 10 Hz、历史 20 帧、未来 10 步与 31 帧事件窗口。BEV 文件共享，不将特征复制到事件中。

## 样本组织

每个已选事件锚点增加 -1 秒、0、+1 秒三种起点，重合的同类别/同锚点只保存一份，优先保留原锚点。记录 `source_event_timestamp_us`、`anchor_offset_us`、`window_role`。这些字段只用于组织与分组分析，不作为模型提示。

背景候选每 3 秒取一个，整个输入和监督窗口外再留 1 秒间隔，避开 DB 中所有 scenario_tag，不只避开 EVENT_TYPES。然后筛除未来横向位移超过 0.3 米、航向变化超过 0.1 弧度或相邻 0.1 秒位移变化超过 0.15 米的候选。它们是未标记且运动平稳的背景对照，不是安全真值；无法仅靠无标签证明没有风险。这些离线筛选条件不作为模型输入。

完整窗口位姿必须有效，八路图像及缓存缺失的窗口不加入清单。`cache_only=True` 严格禁止调用编码器，缺少的 BEV 直接跳过；因此现有缓存覆盖不足时，新增窗口数可能为零，需要单独报告，不能宣称已完成全覆盖。普通预处理会复用现有 BEV，并只提取缺失帧。

## 标签和时序

局部动作为相邻锚点坐标位姿差，旋转到前一步自车坐标。动作 mask 要求两端位姿同时有效。31 帧窗口的因果 mask 为 `[10,31]`，第 k 行只允许索引 `<=20+k`，最后一列永远不可见。

重建后的 schema 为 4；Dataset 读取旧事件时也会重算局部动作与因果 mask，并保留真正的八相机采集时间戳，避免被目标时间覆盖。

划分从每个 DB 的 `log.logfile` 获取录制身份，去除其可选分段后缀，再以录制为单位用 seed 42 划分。完整 DB 名仍用作事件和特征目录。原随机事件清单重建后会变化，不能继续沿用旧验证分数作为独立泛化结果。

## 训练对齐

BEV 行对应 y、列对应 x，使用当前时刻定位变换 `inverse(T_source) @ T_current` 反向采样旧记忆，将其放入当前自车 BEV 网格。特征双线性插值，有效性与年龄最近邻采样；越界标记无效。历史帧逐帧对齐后再更新，后续每个已到达观察也先补偿自车运动。

该变换只补偿自车运动，不使用未来位姿，不把动态目标按未来真值移动。GRU 隐特征的几何平移不等于显式物体跟踪，性能仍需独立测量。当前定位是输入条件，应在实验报告中声明；历史专家运动轨迹不作为动作提示。

## 运行

只重建事件和清单，不改变 BEV：

```bash
conda run -n FRESH-Drive python tools/rebuild_event_windows.py \
  --root ../datasets/nuplan/nuplan-v1.1 --dir mini
```

会更新 `preprocessed_dataset/events/` 内事件文件和 `mini-train.pt`、`mini-val.pt`，旧事件文件未被新清单引用时不进入训练，不自动删除。不要与训练同时重建清单。

需要补提缺失 BEV 时，在上述命令后加 `--extract-missing-bev`；此路径会加载编码器，和仅更新标签的 CPU 路径不同。

Dataset 不提供强制重建参数。首次运行 `preprocess_dataset.py` 时，缺少清单便生成上述新版数据；两份清单存在则跳过预处理。专用重建工具会先移除 train/val 两份清单，再使用同一预处理流程，保留已有事件和 BEV。普通使用者无需设置额外的重建开关。

验证覆盖局部动作往返、因果 mask、偏移去重、背景标签隔离、缓存内容不变、同录制分段不跨集合、平移/旋转方向、越界有效性、未来位姿隔离与对齐梯度，以及 action/refresh 的训练和恢复。

## 本机验证结果

25 项相关测试通过，预处理双文件逐字节一致。扩大运行的图像工具测试中另有 3 项既有契约失败（非有限值、采集时间及错误消息断言）；本次未修改其图像编码实现，不将相关测试报告为全部通过。

64 个 Mini DB 在临时目录 `/tmp/fresh-all-windows-vsjztv0m` 完成缓存复用重建，正式数据盘事件和清单未改写。得到 15,702 个事件窗口：前移 4,672、原锚点 6,031、后移 4,999；训练 14,593、验证 1,109，分别来自 46、5 个独立录制。逐文件确认 schema=4、31 个引用、逐步因果 mask 正确、两集合录制无交叉。真实缓存的位姿和 BEV 范围也通过恒等对齐检查。

2,941 个窗口缺少已有 BEV，28 个背景候选不满足平稳条件，最终背景对照为 0。这证明当前纯缓存迁移不能完成对照补充，不能据此宣布数据集准备完成。下一步需要在可用 GPU 上补提缺失帧后重新统计事件/对照支持量，或另行选取有缓存覆盖的正常对照来源；不能把缺失窗口默认为已补齐。临时目录只是验证产物，不替代正式训练数据。

后续继续检查：当前执行环境没有 `/dev/nvidia*`，`nvidia-smi` 无法连接驱动，实际补提命令在 CUDA 检查处停止，正式缓存未修改。已抽查一个真实 DB 的两个背景候选，31 个位姿均有效，锚点八路图片存在；完整窗口图像仍需补提时逐帧检查。迁移命令结束会分别报告 train/val 的事件和对照数量，对照为零时明确提示数据集未完成。额外修正了记忆对齐中无效单元参与双线性插值的问题，并增加分数平移测试。
