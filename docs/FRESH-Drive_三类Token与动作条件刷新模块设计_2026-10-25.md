# FRESH-Drive：三类 Token 与动作条件刷新模块设计

日期：2026-10-25（Asia/Shanghai）

本文记录已确定的模型方向与后续专用模块接口。当前先验证“视觉特征 → 因果自回归连续动作预测”；动作条件刷新模块是下一阶段的研究设计，本文不表示该模块已实现或有效。

## 1. 任务定义与实施顺序

主任务输入是八路相机空间特征，输出是自车连续局部运动 `[dx, dy, dyaw]`，与真实运动标签计算损失。它是位姿增量预测，不直接等同于方向盘、油门和制动输出。

- 阶段一：全相机按可用时间刷新，训练视觉动作预测基线，验证视觉依赖和陈旧影响。
- 阶段二：固定可靠的动作预测器，引入专用模块，决定每个决策周期是否刷新、刷新哪路相机，并验证其动作收益。
- 阶段三：前两阶段成立后，再研究联合训练、多候选轨迹和 CARLA 闭环学习。

本阶段不引入语言 token。`event_type`、`format_version`、recording 和事件编号用于样本管理、采样或分组评估，不作为驾驶指令。

## 2. 三类 Token 的严格定义

| 表示 | 定义与生成方法 | 用途 |
|---|---|---|
| 视觉 token | 每路相机的空间特征投影到 `D` 维，加入空间位置、相机 ID、采集时间/年龄编码 | 保留各路视觉内容和时间信息 |
| 动作 token | 连续动作或候选轨迹经过 MLP/序列编码器得到的 `D` 维向量 | 表示历史动作或候选动作查询 |
| 刷新 token | 每路相机的可学习刷新 query，与动作查询、旧视觉、年龄和预算交互得到的 `D` 维向量 | 预测证据缺口与刷新价值 |

三者可以使用统一隐藏维度，但不需要共用离散词表，也不需要 Plan-R1 的运动码本。输出的连续动作仍是 `[dx, dy, dyaw]`；它的 embedding 才是内部动作 token。

刷新 token 与 `refresh_mask` 不同：前者是内部向量，后者是选择器输出的八路布尔动作。刷新 query、刷新概率和最终 mask 应分别命名。

当前实现只包含简化的视觉表示和连续动作 embedding，尚无专用刷新 token 或调度器。当前相机全局加权融合属于基线，不能直接提供逐相机的证据缺口分析。

## 3. 保持“选择前预测，选择后获取”的流程

```text
已有相机缓存 + 实际视觉年龄 + 历史记忆
                ↓
       初步连续动作/轨迹预测
                ↓
       候选动作编码为 action query
                ↓
  ActionConditionedRefreshModule（ACRM）
    动作相关空间证据 → 证据缺口 → 刷新收益
                ↓
  预算约束选择：可以不刷新，也可以选择多路
                ↓
       读取/编码被选择的相机图像
                ↓
      更新缓存、采集时间和视觉年龄
                ↓
    动作预测器重新输出连续运动
                ↓
        与真实动作计算损失
```

初步动作仅使用旧缓存和因果可用的状态生成；不能用真实未来动作构造刷新前的 action query。第一版可用一个初步候选 `K=1`，后续再增加多个候选以研究动作排序。

刷新模块应位于相机身份和空间信息被融合丢失之前。每路特征可用小型空间网格压缩后交叉注意力读取，避免一开始就将整张特征图平均为一个向量。

## 4. ACRM 的最小接口

```text
输入：
  cached_tokens      [B, 8, P, D]   # 每路保留 P 个空间 token
  action_queries     [B, K, D]      # 从旧缓存生成的连续候选轨迹编码
  camera_age_s       [B, 8]         # 当前可用时刻 - 实际采集时间
  cache_valid        [B, 8]         # 是否有有效旧缓存
  refresh_available  [B, 8]         # 是否有可获取的有效新帧
  camera_cost        [B, 8]         # 实测编码成本
  budget             [B]           # 本周期允许的预算

输出：
  evidence_gap       [B, K, 8]
  refresh_utility    [B, 8]
  refresh_mask       [B, 8]         # 最终刷新动作
```

自车历史状态和路线条件可在数据接口补充后加入；目前不能假定它们已存在。`refresh_available` 只允许使用传感器到达时间、帧 ID、健康状态等元信息，不能通过新图像内容判断刷新对象。

内部采用动作 query 读取旧空间证据，再得到动作条件证据摘要和缺口，收益头读取该中间变量及年龄、成本和预算。缺口必须实际参与收益计算；如果缺口只是一个并行辅助输出，应称为辅助预测。

第一版的缺口是动作相关证据不足的估计，不自动拥有“行人冲突区”等语义。若缺少独立证据监督，暂不将它宣称为语义正确的解释，需要后续区域干预与中间变量干预验证。

刷新收益应能表达负值：新图像不一定改善同一预测器的动作误差。不要强制“越旧收益越高”，也不要把特征变化幅度直接当成动作价值。

## 5. 同时回答“何时刷新”和“刷新谁”

每个因果决策周期评估刷新价值，不额外预测一个固定未来刷新时刻。选择集合允许为空：

\[
S_t^*=\arg\max_{S\subseteq\{1,\ldots,8\}}
\left[\sum_{v\in S}\widehat U_v-\lambda\sum_{v\in S}c_v\right],
\quad \sum_{v\in S}c_v\le B_t.
\]

- 集合为空：本周期保持旧缓存，回答“现在不刷新”。
- 集合非空：刷新其中相机，回答“现在刷新哪几路”。
- 固定每周期强制 top-k 只能研究刷新对象，不能单独证明学会了刷新时机。

上式是逐相机收益可相加的起点，不保证相机间收益独立。初期可先限制最多一路刷新；扩展多路时，需要用成组干预验证重叠和互补效应，或预测在已选集合条件下的边际收益。

总成本包括初步动作预测、证据推理、选择器、新图像编码和最终动作预测。若预算按周期限定，需要扣除前后规划及调度开销；若使用平均预算或跨周期配额，所有对照遵守相同规则。

更新后的年龄是 `当前可用时刻 - 新帧实际采集时间`，不能无条件置零。没有新帧、缺帧和失效相机应显式处理。旧缓存无法预知完全没有线索的突发事件；最低周期刷新可作为固定机制，但必须计入公平预算并报告其成本。

## 6. 动作损失先保留可比较的候选

损失尚未定稿，第一阶段比较少量选项即可：

| 选项 | 用途与注意事项 |
|---|---|
| 局部动作 L1 / Smooth L1 | 比较逐步位移增量，明确米与弧度的尺度和权重 |
| 周期角度误差 | 用 `atan2(sin(Δyaw), cos(Δyaw))` 等方式处理角度环绕 |
| 累积轨迹损失 | 按 SE(2) 逐步旋转、平移合成位姿后，与锚点坐标下的真实轨迹比较 |

动作 mask 用于剔除无效标签。真实未来运动用于监督；teacher forcing 中可使用当前解码步之前的真实动作作为训练输入，但不能将当前或后续目标送入刷新前的候选生成器。

动作增量误差和轨迹 ADE/FDE 分别报告；当前代码中的 `ade` 实际计算的是局部位移增量误差，不能直接当作累积轨迹 ADE。短时步预测需对比运动外推，避免仅学习惯性运动。

## 7. 用动作结果监督和验证刷新价值

先固定同一个动作预测器 `P`。对于同一缓存状态 `M`，仅将被干预相机替换为当前已到达的新帧，其他输入保持一致：

\[
U_v(S)=D(P(M_S),a^*)-D(P(M_{S\cup\{v\}}),a^*).
\]

其中 `D` 是预先确定的动作或累积轨迹误差，`a*` 只用于训练目标与离线评估。正值表示该次替换减少了误差，负值表示增加误差。训练刷新头预测从旧缓存可推断的期望收益，而不是要求它提前知道新图像的具体内容。

这提供固定模型下的局部日志回放收益监督，不是闭环因果安全真值，也不能直接提供所有未执行候选动作的真实回报。扩展至多候选排序时，需要独立的轨迹/规则评分及其假设，不能把专家单一轨迹拟合误差等同于全部候选的安全价值。

阶段二先使用 `L_action + λ_u L_utility`；获得可信证据监督后再加入 `L_gap`。第一版不同时堆叠没有标签支持的 deadline、regret 和多种解释头。固定硬预算时不必额外重复加入预算损失；软选择训练需处理可微近似及硬选择之间的差异。

## 8. 实验闭环与数据可用性

必须比较：固定刷新频率、轮询、最旧优先、直接预测收益、动作条件证据推理，并固定动作预测器、上下文及预算口径。全相机刷新是高成本参考，不保证在所有误差指标上都是严格上界。

核心证据包括：

1. 相同状态下仅改变相机年龄/对应区域，检查收益预测、刷新选择和动作质量。
2. 替换、随机或打乱证据缺口，检查该变量是否具有实际中介作用，另设同容量直接收益头对照。
3. 按 driving log 独立评测，报告误差下降、真实编码次数、完整延迟、刷新率、漏刷新后的恢复时间和不同随机种子结果。
4. 连续回放中维护真实选择造成的缓存状态，不在每个锚点重新恢复全部新鲜历史。

当前事件缓存可以训练第一阶段，并在已有历史支持范围内构造陈旧替换。四帧历史不自动等同于两秒；陈旧实验的最大年龄必须以实际时间戳覆盖为准。更长陈旧、连续调度和域外验证需要补充相应索引或时段，已有唯一特征仍可复用。

训练/评估进程为了效率预加载特征不自动造成泄漏，关键是这些数据是否进入刷新前的计算路径。建议将“决定刷新”和“获取新特征”分为两个接口，只有后者能向规划器交付所选新特征。

当前基线使用后续日志图像预测后续动作时，评估的是逐时刻获得观测的因果日志回放；它不等于在锚点一次预测完整未来，也不等于车辆偏离专家轨迹后的闭环评估。三种设置需要分别说明。
