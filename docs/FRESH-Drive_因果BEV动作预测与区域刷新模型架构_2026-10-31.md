# FRESH-Drive：因果 BEV 动作预测与区域刷新模型架构

日期：2026-10-31（Asia/Shanghai）  
状态：第一版架构已写入 `model/fresh_drive.py`，正式训练与验收结果尚未获得。

本文是 [两阶段训练与动作预测器有效性验收方案](FRESH-Drive_两阶段训练与动作预测器有效性验收方案_2026-10-31.md) 的实现级补充。它规定输入边界、网络模块、阶段冻结范围和刷新收益接口。数据标签、SE(2) 动作转换、独立 log 划分和验收阈值仍以验收方案为准。

## 1. 设计决定

模型输入是 BEVFormer 已缓存的融合 BEV，不直接读取 JPG，也不把八路相机当作八个模型 token。BEV 特征保留空间网格，便于进行受控的区域替换；第一版刷新单位是 BEV 的 `3×3` 宏区域，不能据此宣称选择了某一路相机。

窗口仍为 10 Hz、历史 20 帧、锚点 1 帧和未来 10 帧：

```text
slot 0..19 : t-2.0 ... t-0.1       历史缓存初始化
slot 20    : t                     锚点时刻的新证据
slot 21..30: t+0.1 ... t+1.0       专家动作监督/离线回放目标
```

主协议在锚点一次生成完整的未来 1 秒动作。动作解码只读取历史与合法锚点信息，绝不读取 slot `21..30`。未来 BEV、未来位姿和未来动作只作为监督或离线收益标签。逐步读取未来日志是补充回放协议，不能与主协议混报。

## 2. 网络总览

```mermaid
flowchart TD
    A[历史 BEV 0..19<br/>特征、valid、真实时间] --> B[空间 Tokenizer<br/>9×9 token + 位置 + age]
    B --> C[逐区域 GRU 记忆<br/>81 个空间 token]
    C --> D[自回归动作 Decoder<br/>前一动作 + step query]
    D --> E[proposal actions<br/>未来 10×[dx,dy,dyaw]]
    C --> F[区域缓存、valid、age]
    E --> G[轨迹条件 Evidence Gap]
    F --> G
    G --> H[有符号 utility U_hat<br/>成本、预算、区域有效性]
    H --> I{空集合或一个 3×3 区域}
    I -->|不刷新| J[保留旧记忆]
    I -->|选中后| K[读取并编码截至 t 的锚点 BEV 区域]
    K --> L[同一冻结预测器重新解码]
    J --> M[最终动作]
    L --> M
    M --> N[SE(2) 累计轨迹]
```

网络分成四个可测试模块：

1. `BEVTokenizer`：把 `[B,C,H,W]` 映射到 `[B,81,D]`，保留空间身份、有效区域和来源年龄。
2. `BEVMemory`：以共享 GRUCell 更新每个空间 token；无效 token 不写入记忆。
3. `ActionDecoder`：用前一步动作和步嵌入查询空间记忆，生成 `[B,10,3]`，不访问完整未来窗口。
4. `FreshModule`：用初步动作 query、旧区域记忆、年龄、有效性、成本和预算预测 9 个有符号收益，并用硬预算选择空集合或一个区域。

## 3. 第一阶段动作预测器

### 3.1 空间表示

默认 `spatial_grid=(9,9)`，每个宏区域包含 `3×3` 个细 token。BEVFormer 的空间特征先经 `1×1 Conv` 投影到 `hidden_dim`，再做自适应池化。空间 Transformer 只在当前帧的 81 个 token 内工作；之后逐 token GRU 依时间顺序读取历史帧。

每个 token 加入：

- 可学习二维位置编码；
- `log(1 + age_seconds)`，年龄由真实时间戳计算；
- 当前 BEV 网格有效性。

无效区域不会更新 GRU 记忆。缺帧不能以全零特征伪装成有效新证据。

### 3.2 因果动作解码

```python
state = model.encode_history(bev[:, :history_features + 1], valid, age)
actions, queries = model._decode(state, target, teacher_forcing=True)
```

解码器在每个步执行：

```text
前一步动作 → action projection
step index  → step embedding
两者相加 → cross-attention 到空间记忆
           → GRU state → [dx, dy, dyaw]
```

训练阶段可将 `a*_{i-1}` 作为第 `i` 步输入；验证、测试和刷新阶段始终使用模型自己的 `a_{i-1}`。当前动作目标不进入当前动作计算路径。

局部动作由 `ActionLoss.trajectory()` 通过 SE(2) 累计为锚点坐标轨迹。动作标签必须由相邻专家位姿在前一姿态局部坐标中构造，不能直接对锚点坐标的 `x/y` 做差。动作损失使用位移和周期航向的 L1 或 Smooth L1；ADE/FDE 直接比较累计轨迹。

### 3.3 锚点访问规则

第一阶段模型使用 `slot 0..20`。训练时可随机丢弃锚点输入（`anchor_dropout`）以减少模型把单个锚点当作唯一证据；该设置不能替代真实陈旧/缺失评估。未来 slot `21..30` 即使在 batch 中存在，也不会进入前向路径。

这一点由以下性质验证：保持历史和锚点不变，只改变未来 BEV，`actions` 应保持相同；改变未来专家动作也不能改变推理结果。

## 4. 第二阶段刷新模块

### 4.1 选择前

第二阶段先只用历史 `slot 0..19` 建立旧缓存，得到初步轨迹 `proposal_actions`。`FreshModule` 接收：

```text
旧空间记忆 [B,81,D]
旧 valid / age
初步动作 query [B,10,D]
区域成本、可用性和预算
```

它首先生成区域 `gap`，再将 `gap` 送入 utility head，输出 `refresh_utility [B,9]`。因此 gap 是收益计算路径中的瓶颈，不是与 utility 并行的解释文本头。没有语义标注时，gap 只能解释为操作性的证据缺口表示，不能命名为“行人缺失”等语义。

### 4.2 硬预算选择

默认每个区域成本为 1、预算为 1。选择集合为：

```text
{空集合, {region_0}, ..., {region_8}}
```

只有区域可用、成本不超过预算且预测净收益为正时才选择。负收益、零收益或无可用区域都允许空选择。第一版不假设多区域收益可加，也不支持 `max_refresh>1`。

### 4.3 选择后

只有完成选择后，模型才读取锚点 `slot 20` 的特征，并使用所选区域掩码编码。未选区域不能流入 gap、utility、记忆更新或最终动作。旧状态和每个候选区域的状态从同一个快照独立复制，不能把九次候选串行累积。

最终轨迹与 proposal 使用相同的未来绝对目标时间。区域选择本身只证明 BEV 表示层的更新价值；完整系统成本还要计入特征获取、对齐、两次规划和 I/O。

## 5. 真实收益标签

对冻结预测器先计算旧视觉重规划 `τ⁰`，再逐区域替换当前真实证据得到 `τʳ`：

\[
U_r = D(τ^0, τ^*) - D(τ^r, τ^*) .
\]

当前实现的 `fresh_targets()` 直接执行 9 个独立区域分支，保留正、零和负收益。`τ*` 仅是专家目标，不进入选择前网络。收益头使用 Huber 回归；硬选择不通过动作损失反向传播。

还需独立报告原规划 `κ`、旧视觉重规划 `τ⁰` 和更新后轨迹 `τʳ`。`U_r>0` 只说明视觉更新优于旧视觉重规划，不自动说明它优于原规划；后者使用 `W=D(κ,τ*)-D(τʳ,τ*)`。

## 6. 训练与冻结

### 阶段一

```text
输入：历史 + 锚点 BEV、valid、真实时间
训练：Tokenizer + Memory + Decoder
监督：future_actions；可选累计 future_trajectory loss
验证：自回归，不使用 teacher forcing
输出：经 A/B 验收的动作预测器 checkpoint
```

### 阶段二

```text
加载阶段一 checkpoint
冻结并 eval：Tokenizer、Memory、ActionDecoder
训练：FreshModule
监督：冻结模型离线测得的 U_r
输出：区域收益估计与预算选择器
```

第二阶段不能从随机动作预测器开始，也不能让刷新模块自由生成动作 latent 变成第二个规划器。训练中预测器权重和 `eval` 状态都应检查；隐藏状态会随合法输入改变，这不违反冻结。

## 7. 当前实现与后续必须完成的工作

已实现的架构接口：

- 主动作 forward 不读取未来 BEV；
- 9 区域、空选择和单区域硬预算；
- 轨迹 query → gap → signed utility；
- 真实区域替换的 `fresh_targets()`；
- 第二阶段冻结预测器；
- 实际时间戳和有效 mask 进入年龄/读取路径。

开始正式训练前仍需完成并验证：

1. 重新预处理或确认事件缓存中的 `bev_valid_mask`、时间戳和局部动作标签符合 schema；旧缓存不能未经核对直接复用。
2. 将 `model/README.md`、数据集字段和工具测试同步到新接口。
3. 修正正式划分为独立 driving log 后，再报告泛化结果；事件随机划分只作开发诊断。
4. 在独立 log 上运行未来信息扰动、SE(2) 重建、区域替换、预算和冻结梯度测试。
5. 预先锁定 ADE/FDE、视觉增益、收益幅度、有效场景数和统计区间阈值。

世界模型、自然语言思维链、CARLA 闭环和联合微调属于后续扩展，不能在第一版动作预测器尚未验收时混入主结果。
